# RC-8 — real assistive-technology pass (Orca, 2026-09-11)

> **Status: measured record.** The "≥1 real assistive-tech pass logged" half of RC-8
> (`fundamental-release-gate-spec.md` §3.1). The automated half (`contracts/a11y.test.ts`,
> `reduced-motion.test.ts`) runs in CI on every change; this document is the screen-reader pass,
> reproducible with `scripts/a11y/orca-pass.sh` on the `titan-gpu` host.

## What was tested

| | |
|---|---|
| Screen reader | **Orca 42.0** (GNOME), Chromium script (`orca.scripts.toolkits.Chromium`) activated on window activation |
| Browser | Google Chrome 149.0.7827.155, Linux (Ubuntu 22.04), `--force-renderer-accessibility` |
| Accessibility bus | AT-SPI2 (`at-spi-bus-launcher`), Xvfb `:99` 1600×900, openbox as window manager |
| Pages | `/` (homepage) and `/eli5`, served from the built site (`pnpm preview`, same bundle as production) |
| Field configuration | homepage `<field-root render="dots" overlay="off" grid-warp="3" …>`; `/eli5` its own field; both with the nav's flow/heatmap/grid toggles |
| Speech capture | Orca's speech layer (`SPEECH OUTPUT:` in its debug log) — the exact text handed to the synthesizer; the host has no audio device, so the speech-dispatcher connection is refused on purpose and Orca logs instead of speaking |

Each pass drives the same three things a screen-reader user does:

1. **Say All** from the top of the document (`KP_Add` / `Insert+;`) — Orca reads the page linearly.
2. **Tab order** — 25 × `Tab` through the focusable elements.
3. **Browse-mode line reading** — 25 × `Down` through the content.

The AT-SPI tree Orca reads (the same bus) is walked afterwards with `scripts/a11y/atspi-walk.py`
and saved next to the transcript.

## Result — pass

**The field is announced as nothing, and the page's real content is fully navigable.**

| Page | Orca utterances | Page summary Orca gave on load | Field / canvas announced |
|---|---|---|---|
| `/` | 1 097 | "Page has 5 landmarks, 14 headings, 1 visited link, 68 unvisited links." | **none** |
| `/eli5` | 1 077 | "Page has 6 landmarks, 32 headings, 33 unvisited links." | **none** |

Evidence, per page (files in `rc8-at-pass-2026-09-11/`):

- `*-orca-utterances.txt` — every utterance, in order. Say All walks banner → navigation (skip link, the
  site links, the three field-overlay toggle buttons announced as "toggle button, not pressed / pressed")
  → "leaving navigation. leaving banner. main content" → the headings and prose → footer. Tab lands on
  links and buttons only; Down reads line by line. No utterance names a canvas, image, figure or graphic
  belonging to the field. (The homepage's five "figure" utterances are the authored pipeline diagram —
  `data-*` → measure → `--field-*` → CSS — a real `<figure>` with a caption, not the field; "Canvas" once is
  the text of a nav item.)
- `*-atspi-tree.txt` — the accessibility tree as exposed to Orca: `document web` → `landmark` (banner,
  navigation "Primary", main, footer) → headings, links, static text. **Zero `canvas`, `image` or
  `graphic` nodes on either page.** `<field-root>` appears only as the *text* of a prose mention
  ("`<field-root>` · elements" in the use-case cards). This is the `aria-hidden="true"` that
  `<field-root>`/`<field-cell>` set on connect (`packages/elements/src/index.ts`, `field-cell.ts`) and
  that the overlay canvas gets (`index.ts`), doing exactly what `support-matrix.md` §Accessibility
  promises.
- Motion never carried meaning: everything Orca read is the semantic HTML; the `--field-*` variables
  only style what the reader already announced.

Noise to ignore in the transcripts: the tail of each Tab phase cycles through Chrome's own "Can't
update Chrome / Reinstall Chrome" infobar (the host's Chrome is installed outside apt) — browser
chrome, not page content.

## How to reproduce

On a Linux host with `orca`, `xvfb`, `openbox`, `at-spi2-core`, `dbus-x11`, `xdotool`,
`python3-pyatspi` and Google Chrome (the `titan-gpu` runner has all of these):

```bash
# serve the built site somewhere the host can reach (here: pnpm preview on :4399)
bash scripts/a11y/orca-pass.sh http://127.0.0.1:4399/      home 70
bash scripts/a11y/orca-pass.sh http://127.0.0.1:4399/eli5  eli5 60
# → /ai/tmp/fe-a11y/<label>/{announcements.txt,atspi-tree.txt,orca-debug.log}
```

Two things the script does that are easy to get wrong: it starts a window manager (without one Chrome is
never the *active* window and Orca ignores every event as "not from active app"), and it launches Chrome
only after Orca logs `ORCA: Initialized` so the window-activation event reaches Orca.

## What this does not cover

- One engine (Orca). VoiceOver (macOS/iOS) and NVDA (Windows) are a maintainer spot-check, listed as
  optional in the support matrix; the `aria-hidden` mechanism is engine-independent.
- The Lab and pattern pages. The two pages here carry the largest fields on the site; the same
  `<field-root>` element class is used everywhere.
- Braille (BrlAPI is not running on the host; Orca's braille layer was exercised to the extent that it
  formats every utterance — see `BRAILLE LINE:` in the debug log — but no display was connected).
